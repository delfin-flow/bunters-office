# 02 — v0.1.0: identity, the feedback board, version and update, the package repo (S12, S13, S14, S15, S16)

**Delivered**
- `charters/bunter.md` (who the assistant is) and README rewritten as the product's front page.
- The issue board as an agentic feedback channel: a compatibility form, a privacy line, and the split
  between local adaptation (`store/adaptations.md`) and upstream repair.
- `scripts/version.sh` + `scripts/update.sh` (fast-forward only, incoming changelog first, never touches the
  record) and the package as its **own** git repository with its own changelog.
- `skills/` as the instruction layer over the deterministic scripts.

**Decisions & deviations**
- `AGENTS.md` became a stub pointing at `WORKSPACE.md` (D14): people understand "workspace", clients load
  `AGENTS.md`.
- The installer no longer deletes the upstream remote (D13), reversing the first design: the workspace must
  be able to compare itself with GitHub.

**Known issues**
- The update flow was tested against a local bare remote, not GitHub over the network.
- `templates/store/` was briefly untracked because `.gitignore` matched `store/` unanchored; fixed, and the
  class of bug is now the reason `store/` is anchored at the root.

**Hand-off to next story**
Anything that touches git history belongs in `install.sh`/`update.sh` only; agent-side changes must not run
those commands unprompted.
