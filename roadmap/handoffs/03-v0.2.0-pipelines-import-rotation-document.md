# 03 — v0.2.0: named pipelines, document import, rotation, the readable document (S17)

**Delivered**
- `charters/pipelines.md`: five flows (collect, import, secrets & rotation, document, bundle) with invariants.
- `skills/import-document` — an existing document is untrusted input: verify each claim with the person,
  quarantine credential-shaped material, produce a gap list.
- `skills/handle-secrets` + `store/secrets-rotation.csv`: locators only, free vault options, plaintext
  credential = exposed = rotate; `status.sh` reports overdue, due-soon and cannot-rotate.
- `scripts/document-export.sh` + `templates/document/HANDOVER.md`: one printable document with tickable steps.

**Decisions & deviations**
- The document is **generated**, never hand-edited (D16): if it is wrong, the record is wrong.
- Rotation order is specified (provider first, then vault, then the date) because a rotation that locks the
  owner out is worse than an old password.

**Known issues**
- No real imported document has been through P1; the ten-page document that started this project is the
  obvious first test and is not in the repository (by design — it holds secrets).

**Hand-off to next story**
P1's verification loop is the part most likely to be shortened under time pressure. If it is shortened, say
so in the log rather than presenting unverified claims as facts.
