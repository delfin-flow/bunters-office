# Access resilience — a second person, a second device, and a quick way back in

Accounts are lost when they depend on one person and one device. This procedure records, for each critical
account, the **second person**, the **parallel devices** and the **backup codes** that make access
recoverable fast — without the owner (`charters/authority.md`).

## The three things every critical account needs

1. **A second authorised person** — most providers let you name a second admin, delegate or manager. That
   person can act lawfully when the owner cannot, and never by impersonation.
2. **Parallel 2FA devices** — a second device (phone, tablet, security key) enrolled on the account, so
   losing one device does not lock everyone out.
3. **Backup / recovery codes** — generated once, stored where the second person can reach them, and treated
   as credentials: vaulted, never written as values in this record.

## Regaining access quickly

For each row, the **regain path** is the shortest lawful route back in: the second admin, the second 2FA
device, the backup codes, or the provider's support route with the recorded evidence. If that path is
empty, losing access means waiting on the provider — record it as a gap (`store/gaps.md`).

## Safe steps

Naming a second admin, enrolling a second device and generating backup codes are reversible settings on the
provider's own page. Removing the owner, transferring ownership, or disabling 2FA is **not** part of this
checklist — those need explicit, logged approval (`charters/authority.md`).
